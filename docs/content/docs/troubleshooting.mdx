---
title: Troubleshooting
description: Find the fix by what you notice or the message you see.
---

Start with `claudio doctor`, from your project directory. It checks every part in order, and each ✗ line names the fix. [Commands](/docs/reference/cli#claudio-doctor) lists each check.

If every line is ✓, find what you notice below. Warnings start with `!` in the transcript, and notes with `·`. Two logs hold the details:

```bash
tail -n 20 ~/.config/claudio/brain.log
cat ~/.config/claudio/helper.log
```

If `claudio` stops at start with `ModuleNotFoundError` after an update, a newer version needs a package your install doesn't have yet. Update with `uv tool upgrade claudio`; for an install from a local checkout, run `uv tool install --editable . --force` in it.

## Listening

<Accordions type="multiple">
<Accordion title="It doesn't hear me" id="it-doesnt-hear-me">

Look at the state line under the transcript:

- **The level bar stays flat**: macOS has not given your terminal the microphone. Open System Settings, then Privacy & Security, then Microphone, and turn it on for cmux or the terminal you run claudio in. Restart claudio.
- **It reads `muted · say /unmute`**: say “slash unmute”, or type `/unmute`.
- **It reads `push to talk · Enter opens the mic`**: press <kbd>Enter</kbd> before you talk, or turn push to talk off with `claudio set push_to_talk false`.
- **Your words show dim**: `address_me` is on, so only turns that start with its name count (“claudio”, or the `name` you gave it). Say the name and “slash address me off”, or run `claudio set address_me false`.
- **It reads `ears lost · reconnecting`**: see [ears lost](#ears-lost).

</Accordion>
<Accordion title="· ears lost (…); reconnecting in 1s" id="ears-lost">

claudio cannot reach Deepgram Flux. It retries after 1, 2, 4 and 8 seconds, then every 15 seconds, until it connects.

Check your connection, then check the key with `claudio doctor`. If it never reconnects, check the `ears` setting: it must be a Flux model, such as `flux-general-en`.

</Accordion>
<Accordion title="It cuts me off before I finish" id="cuts-me-off">

Your turn ends too early. Wait longer for it:

```bash
claudio set eot 0.8
claudio set eot_timeout_ms 2500
```

[Listening and turns](/docs/configure/listening#tune-when-your-turn-ends) explains both settings.

</Accordion>
<Accordion title="It waits too long after I stop" id="waits-too-long">

Your turn ends too late. End it sooner:

```bash
claudio set eot 0.6
```

If it still waits, lower `eot_timeout_ms` to `1000`.

</Accordion>
<Accordion title="It hears itself, or stops itself mid-reply" id="hears-itself">

The banner reads `echo cancel off`, so the mic hears the speakers. Pick one fix:

- Install the Xcode command line tools with `xcode-select --install`, then restart claudio. It builds the echo canceller once.
- Use headphones.
- Turn barge-in off with `claudio set barge_in false`, and cut replies with <kbd>Enter</kbd>.

</Accordion>
<Accordion title="! echo canceller did not build; using the plain mic (headphones for barge-in)" id="echo-canceller-did-not-build">

`swiftc` failed to build the echo canceller. The warning ends with the compiler's last lines. claudio carries on with the plain mic, so barge-in needs headphones.

Reinstall the Xcode command line tools with `xcode-select --install`, then restart claudio. It tries the build again on every start until it succeeds.

</Accordion>
<Accordion title="! echo canceller stopped: …; using the plain mic (headphones for barge-in)" id="echo-canceller-stopped">

The echo canceller exited while claudio ran, and claudio switched to the plain mic and speaker for the rest of the run. The text after `stopped:` is the last line of `helper.log`. Until you restart, barge-in needs headphones.

If it stops on every run, delete the built helper so it is rebuilt on the next start:

```bash
rm ~/.config/claudio/bin/claudio-audio
```

</Accordion>
</Accordions>

## Replies

<Accordions type="multiple">
<Accordion title="! slow: 3.4 s to first word" id="slow">

The reply took more than 3 seconds from the end of your turn to its first word. The state line shows this time for a few seconds after each reply. To speed it up, from most to least effect:

- Lower the effort, if you raised it: `claudio set effort low`.
- Pick a faster model: `claudio set model haiku` or `claudio set model sonnet`.
- Let the brain start earlier: `claudio set eager_eot 0.2`.

</Accordion>
<Accordion title="! mouth lost" id="mouth-lost">

You see one of these:

- `! mouth lost: the speech service is unreachable; text only`
- `! mouth lost mid-reply; the rest is text only`

claudio could not connect to the speech service, twice, one second apart. The reply is shown as text, and the next reply tries again. Check, in order:

1. Your connection.
2. The voice name, which claudio does not check: `claudio set voice aura-2-orion-en` restores the default.
3. For ElevenLabs, the `elevenlabs_api_key` in `secrets.json` and the `elevenlabs_voice` id. `claudio set mouth deepgram` switches back to Aura.

</Accordion>
<Accordion title="It still speaks with Aura after switching to ElevenLabs" id="still-aura">

`mouth` is `elevenlabs`, but claudio has no ElevenLabs key, so Deepgram speaks instead. Add `elevenlabs_api_key` to `~/.config/claudio/secrets.json`, then run `claudio set mouth elevenlabs` again so claudio reloads it. If you exported `ELEVENLABS_API_KEY`, restart claudio from that shell.

</Accordion>
<Accordion title="! the brain died; restarting it" id="brain-died">

The `claude` process exited. claudio restarts it, and the brain says it is back and asks you to repeat yourself if you were mid-request.

If it keeps happening, the reason is at the end of `brain.log`:

```bash
tail -n 20 ~/.config/claudio/brain.log
```

Then check that Claude Code works and is signed in, outside claudio:

```bash
claude -p "say hi"
```

</Accordion>
<Accordion title="· the remembered conversation is gone; starting fresh" id="conversation-gone">

claudio tried to resume the last conversation, and `claude` could not resume it. claudio drops it and starts a fresh brain. Nothing to fix. Earlier days stay in the transcripts.

</Accordion>
<Accordion title="It talks too much, or too little" id="too-much">

Switch the style: `claudio set style brief` for one sentence a reply, `plain` for the persona as written. For lasting changes, edit the [persona](/docs/configure/persona).

</Accordion>
</Accordions>

## Sessions

<Accordions type="multiple">
<Accordion title="A session never reports back" id="no-reports">

Check, in order:

1. **The hooks are not installed.** `claudio doctor` shows it. Run `claudio install`.
2. **The session started before the hooks.** A session loads its hooks when it starts. Restart it.
3. **It is not in cmux.** claudio only hears from sessions in a cmux workspace.
4. **You did not hand it the work.** With `narrate` set to `handed-off`, the default, only finishes of work the brain handed over in the last 30 minutes are narrated. `claudio set narrate all` narrates every finish.
5. **You are muted, or `narrate` is `none`.** Say “slash unmute”, or run `claudio set narrate handed-off`.

</Accordion>
<Accordion title="It sends work to the wrong session" id="wrong-session">

Ask “slash status” to hear which orchestrator is set. Change it by saying “the orchestrator is Core now”, or from the shell:

```bash
claudio set orchestrator Core
```

A change from the shell reaches the brain at its next restart, so tell it, or restart claudio. A `.claudio.json` in the project may also be setting `orchestrator`, and it wins over `claudio set`.

</Accordion>
</Accordions>

## Settings and setup

<Accordions type="multiple">
<Accordion title="! …/config.json: eot must be between 0.0 and 1.0, not 1.5; keeping 0.7" id="a-setting-is-refused-or-skipped">

A setting has a bad value. It is skipped, and the value before it is kept. The warning starts with where the value came from: the path of `config.json`, `.claudio.json`, or `environment`. Fix it there. `claudio set` refuses the same values with the same reason, and saves nothing.

| Message | Fix |
|---|---|
| `barge_in must be true or false, not 'maybe'` | `true`, `false`, `yes`, `no`, `on`, `off`, `1` or `0` |
| `eot_timeout_ms must be a whole number, not '1500.5'` | a whole number, such as `1500` |
| `eot must be a number, not 'x'` | a number, such as `0.7` |
| `eot must be between 0.0 and 1.0, not 1.5` | a number in that range |
| `style must be one of plain, brief, caveman, not 'fast'` | one of the listed values, in lower case |
| `voice cannot be empty` | any text; only `orchestrator` may be empty |
| `voice must be text, not 5` | a quoted string in the JSON file |

</Accordion>
<Accordion title="No Deepgram key. Run `claudio setup`, or export DEEPGRAM_API_KEY." id="no-deepgram-key">

claudio has no Deepgram key, so it cannot listen. Run `claudio setup`, or export the key before you start claudio:

```bash
export DEEPGRAM_API_KEY=your_deepgram_key
```

</Accordion>
<Accordion title="that key was refused by Deepgram" id="key-refused">

Deepgram rejected the key during setup. Copy a working key from console.deepgram.com and try again. After three refusals, setup stops with `no working Deepgram key; setup stopped`.

</Accordion>
<Accordion title="claudio install says settings.json could not be read" id="install-refused">

`~/.claude/settings.json` is not valid JSON, is not a JSON object, or its `hooks` section is not shaped the way Claude Code writes it. Nothing was changed. Fix the file, then run:

```bash
claudio install
```

</Accordion>
</Accordions>
