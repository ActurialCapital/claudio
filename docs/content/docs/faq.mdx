title: FAQ
description: Short answers to common questions about platforms, cost, privacy and what the brain may do.
---

Short answers, each with a link to the page that covers it in full. For something that isn't working, see [Troubleshooting](/docs/troubleshooting).

<Accordions type="multiple">
<Accordion title="Does it work on Linux or Windows?">

No. The echo canceller is Apple's voice-processing unit, and your sessions live in cmux, which is a Mac app.

</Accordion>
<Accordion title="What does it cost?">

The brain runs through your Claude Code login, so it uses your Claude plan like any other session. Deepgram bills the listening and, with the default mouth, the speaking. ElevenLabs bills the speaking if you [switch the mouth](/docs/configure/voice#switch-the-mouth-to-elevenlabs) to it.

</Accordion>
<Accordion title="Can it change my code?">

Not unless you allow it. Out of the box the brain can read and search files, run `git status`, `git log`, `git diff` and `git branch`, read GitHub with `gh` (issues, pull requests, search), use a few cmux commands to message, list, read and open sessions and to select the option you chose in a session's question, and run `claudio set`. Work goes to your sessions, which run with their own permissions. Anything more is up to you: say yes or always when it asks, or list it in `settings.json`. See [what the brain may do](/docs/reference/files#what-the-brain-may-do).

</Accordion>
<Accordion title="Can it answer a session's prompts for me?">

- **Permission prompts**: no. It reads the prompt out and tells you which session asked; you answer in that session's pane. The brain is told never to press keys for a permission prompt.
- **Multiple-choice questions**: yes. It reads the options aloud, you say which one, it confirms, then selects it in the session's pane with `cmux send-key`.

</Accordion>
<Accordion title="Does the brain use my CLAUDE.md or my Claude Code settings?">

Your CLAUDE.md, yes. Your settings, no.

- **CLAUDE.md**: the brain reads the CLAUDE.md files that Claude Code loads for the project you run claudio in, like any session. Keep instructions there that you are happy for the voice to follow too.
- **Settings**: the brain starts with `--setting-sources ""`, so your `settings.json` files do not apply to it: not your permissions, hooks or env. Which tools it may use is set by claudio, plus what you allow in `~/.config/claudio/settings.json`, and it can't read `~/.config/claudio/secrets.json`.
- **MCP servers**: none of yours, only those you list in `~/.config/claudio/mcp.json`.
- **Skills and slash commands**: none. Its prompt lists claudio's own slash commands, so it can tell you about them.

Your sessions use your settings as usual.

</Accordion>
<Accordion title="Where do my voice and words go?">

Your audio goes to Deepgram to be transcribed. What you say goes to Claude, as the brain's turns. Replies go to Deepgram, or ElevenLabs, to be spoken. Transcripts and logs stay on your Mac, under `~/.config/claudio`.

</Accordion>
<Accordion title="Can I use it in another language?">

Set `ears` to `flux-general-multi`, edit the [persona](/docs/configure/persona) so the brain answers in your language, and pick a voice that speaks it. See [other languages](/docs/configure/listening#talk-in-another-language).

</Accordion>
<Accordion title="Can I use it with other people in the room?">

Turn on `address_me` with `claudio set address_me true`. Then only turns that start with "claudio" count, and the rest show dim in the transcript.

</Accordion>
<Accordion title="How do I use different settings per project?">

Put a `.claudio.json` in the project and run claudio from there. Any setting except the API keys can go in it. See [per-project settings](/docs/configure/settings#change-a-setting).

</Accordion>
<Accordion title="Why does it sometimes say 'Looking.' or 'Checking.'?">

The persona asks the brain to say what it's about to do before each tool call. When the brain skips that, claudio fills in one word, "Looking." before it reads or searches files and "Checking." before anything else, so you don't sit through silence.

</Accordion>
<Accordion title="It says it isn't allowed to run something. How do I allow it?">

Answer the question. When the brain needs a command its rules don't cover, the command waits and claudio asks, in the same reply: “I'm not allowed to run `gh pr create`. May I? Say yes, always, or no.” Yes runs it once; always also adds the rule to `~/.config/claudio/settings.json`, for every later run; no, or a minute's silence, doesn't run it.

You can also edit that file yourself, in [Claude Code's settings format](https://code.claude.com/docs/en/settings#permission-settings), such as `{"permissions": {"allow": ["Bash(gh:*)", "WebFetch"]}}`; saving it restarts the brain. Telling the brain “I approve” does nothing on its own: only claudio's question can allow it. See [allow more](/docs/reference/files#allow-more).

</Accordion>
<Accordion title="Does quitting claudio clear the conversation?">

No. With `memory` on, the brain resumes the same conversation the next time you start claudio, if it's less than 7 days old, so Ctrl-C and a restart keep everything it said and believed. That includes a wrong conclusion, such as "the cmux tools are down" after an outage that has passed. To start fresh:

- say "slash clear", or type `/clear`, while it runs
- run `claudio forget` before the next start
- run `claudio set memory false` to start fresh every time

None of these delete your transcripts. See [what the brain remembers](/docs/guide/talking#what-the-brain-remembers).

</Accordion>
<Accordion title="How do I remove it?">

Remove the hooks first, then the tool, then its files:

```bash
claudio uninstall
uv tool uninstall claudio
rm -rf ~/.config/claudio
```

The last line deletes your settings, keys, persona and transcripts.

</Accordion>
</Accordions>
