claudio keeps its files in `~/.config/claudio`, or in `$XDG_CONFIG_HOME/claudio` when `XDG_CONFIG_HOME` is set:

| Path | What it is |
|---|---|
| `config.json` | your settings |
| `secrets.json` | your API keys, mode 600 |
| `prompt.md` | your additions to the [persona](/docs/configure/persona), added after claudio's own rules from the package |
| `transcripts/YYYY-MM-DD.md` | each day's conversation, one line each with the time to the second: your turns, its replies and what it showed, session reports, the commands the brain ran, setting changes, notes and warnings |
| `session` | the remembered brain session id and when it started |
| `mcp.json` | optional: MCP servers for the brain, in the same format as a project's `.mcp.json` |
| `allow` | optional: more tools for the brain, one Claude Code permission rule per line |
| `brain.log` | the brain's error output, appended across runs |
| `helper.log` | the echo canceller's error output, rewritten each run |
| `bin/claudio-audio` | the echo canceller, built once from `audio.swift`, and rebuilt when that file is newer |

The `session` file is used only when `memory` is on and it is less than a week old. `claudio forget` and “slash clear” delete it. A key left in `config.json` by an older version is moved to `secrets.json` the next time the settings are read.

claudio also uses these paths:

| Path | What it is |
|---|---|
| `.claudio.json` in the current directory | [per-project settings](/docs/configure/settings#per-project) |
| `~/.claude/settings.json` | where `claudio install` adds the hooks |
| `settings.json.bak-claudio` | the copy taken before each install or uninstall, next to the real `settings.json` behind any symlink |
| `/tmp/claudio-<uid>.sock` | the socket the hooks report to, present only while claudio runs |

## What the brain may do

The brain is one `claude -p` process, started in the directory you ran claudio from. It loads no Claude Code settings files, so the permissions, hooks and environment in your `settings.json` files do not apply to it. It does read `CLAUDE.md` files, both the project's and your own, like any Claude Code session. It may use only:

- **Read**, **Grep** and **Glob**, on any file except `secrets.json`
- **git**: `status`, `log`, `diff` and `branch`
- **gh**, to read GitHub: `issue view`, `issue list`, `pr view`, `pr list`, `pr diff`, `pr checks`, `repo view` and `search`, with your `gh` login
- **cmux**: `agent message`, `surface list`, `read-screen`, `new-workspace`, `new-split`, `new-surface` and `send-key`
- **claudio set**, to change a setting when you ask
- **MCP servers** listed in `mcp.json`, every tool of each one; with no `mcp.json`, none

It gets none of your Claude Code skills or slash commands, which it would otherwise offer as claudio's; its prompt lists claudio's own. It never gets the MCP servers of your own Claude Code setup either: a desktop tool that disconnects would otherwise confuse it into thinking it can't check a session. To give it a server, list it in `mcp.json`; saving the file restarts the brain with it:

```json title="~/.config/claudio/mcp.json"
{"mcpServers": {"notes": {"command": "npx", "args": ["-y", "some-notes-mcp"]}}}
```

- **anything you list in `allow`**

Your Claude Code permission settings don't apply to it, and `claude -p` has no approval prompt. Instead, when the brain is refused a command, claudio itself asks: “I'm not allowed to run `gh pr create`. Allow it from now on? Say yes or no.” Answer by voice or by typing:

- **yes** (or yeah, sure, okay, allow): `Bash(gh pr create:*)` is added to `allow`, the brain restarts with it, and your request runs again
- **no**: nothing is added
- **anything else**: an ordinary turn; the question still stands for one more, so you can ask what it means first

When it's a folder outside the one you started in that was refused, claudio asks about the folder instead, the whole repo when it's in one: “I'm not allowed into ~/GitHub/ActurialCapital/claudio. Allow it from now on?”

The rule covers the command's first plain words, up to three, so a yes to `gh pr create` doesn't allow all of `gh`. claudio asks, not the brain, so nothing the brain reads can approve itself.

### Allow more

Put one [Claude Code permission rule](https://code.claude.com/docs/en/settings#permission-settings) per line in `~/.config/claudio/allow`. Blank lines and `#` comments are skipped:

```text title="~/.config/claudio/allow"
# all of gh, not just reading
Bash(gh:*)
# fetch web pages
WebFetch
# a folder outside the one you start claudio in
~/GitHub/ActurialCapital/claudio
```

A line that is a path is a folder the brain may read and search in, as well as the one you start claudio in: `claude -p` refuses anything outside those, whatever the other rules say.

Saving the file, or `mcp.json`, restarts the brain with it, keeping the conversation. Anything you allow, the brain can run without asking, so allow only what you'd let it do unwatched. It presses keys in a session's pane only to select the option you chose in that session's question, never for a permission prompt. Work goes to your sessions.

Its model and effort come from the `model` and `effort` settings. With `model` set to `default`, it uses your Claude Code default.
