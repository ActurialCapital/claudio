claudio keeps its files in `~/.config/claudio`, or in `$XDG_CONFIG_HOME/claudio` when `XDG_CONFIG_HOME` is set:

| Path | What it is |
|---|---|
| `config.json` | your settings |
| `secrets.json` | your API keys, mode 600 |
| `prompt.md` | your additions to the [persona](/docs/configure/persona), added after claudio's own rules from the package |
| `transcripts/YYYY-MM-DD.md` | each day's conversation, one line each with the time to the second: your turns, its replies and what it showed, session reports, the commands the brain ran, setting changes, notes and warnings |
| `session` | the remembered brain session id and when it started |
| `learned.md` | rules the brain kept from your corrections, one a line, added to the end of the persona; edit or empty it freely |
| `mcp.json` | optional: MCP servers for the brain, in the same format as a project's `.mcp.json` |
| `settings.json` | optional: more tools and folders for the brain, in Claude Code's settings format; "always" adds to it |
| `allow.bak` | the older one-rule-per-line `allow` file, kept after its rules moved into `settings.json` |
| `brain.log` | the brain's error output, appended across runs |
| `helper.log` | the echo canceller's error output, rewritten each run |
| `bin/claudio-audio` | the echo canceller, built once from `audio.swift`, and rebuilt when that file is newer |

The `session` file is used only when `memory` is on and it is less than a week old. `claudio forget` and “slash clear” delete it. A key left in `config.json` by an older version is moved to `secrets.json` the next time the settings are read.

claudio also uses these paths:

| Path | What it is |
|---|---|
| `.claudio.json` in the current directory | [per-project settings](/docs/configure/settings#per-project) |
| `~/.claude/settings.json` | where `claudio install` adds the hooks |
| `settings.json.bak-claudio` | the copy taken before each install or uninstall, next to the real `settings.json` behind any symlink |
| `/tmp/claudio-<uid>.sock` | the socket the hooks report to, present only while claudio runs |

## What the brain may do

The brain is one `claude` process, run through the Claude Agent SDK and started in the directory you ran claudio from. It loads no Claude Code settings files, so the permissions, hooks and environment in your `settings.json` files do not apply to it. It does read `CLAUDE.md` files, both the project's and your own, like any Claude Code session. It may use only:

- **Read**, **Grep** and **Glob**, on any file except `secrets.json`
- **git**: `status`, `log`, `diff` and `branch`
- **gh**, to read GitHub: `issue view`, `issue list`, `pr view`, `pr list`, `pr diff`, `pr checks`, `repo view`, `repo list` and `search`, with your `gh` login
- **cmux**: `agent message`, `surface list` and `read-screen`, and `workspace create` (or the older `new-workspace`), `new-split` and `new-surface` only to start `claude` (`--command claude`); a shell or any other program there is asked about, and `--layout` or `--env` is refused
- **claudio set**, to change a setting when you ask
- **claudio learn** and **claudio unlearn**, to keep a correction of yours in `learned.md`, or drop one
- **claudio choose**, to answer a session's multiple-choice question with the option you picked
- **notes**: create and edit `.md` and `.txt` files in `~/Desktop` and `~/Documents`, and check that a file exists with `test`
- **`claudio open`** and **`claudio close`**: a web link in your browser, or a `.md` or `.txt` note from those folders in TextEdit, never an app, a script or anything else; closing a note saves it and quits TextEdit when it was the last window. The first close asks macOS for permission to control TextEdit
- **the web**: WebSearch and WebFetch
- **MCP servers** listed in `mcp.json`, every tool of each one; with no `mcp.json`, none

It gets none of your Claude Code skills or slash commands, which it would otherwise offer as claudio's; its prompt lists claudio's own. It never gets the MCP servers of your own Claude Code setup either: a desktop tool that disconnects would otherwise confuse it into thinking it can't check a session. To give it a server, list it in `mcp.json`; saving the file restarts the brain with it:

```json title="~/.config/claudio/mcp.json"
{"mcpServers": {"notes": {"command": "npx", "args": ["-y", "some-notes-mcp"]}}}
```

- **anything you list in `settings.json`**

It can't read `secrets.json` with Read, nor with a command that names it, and it can't write anything in `~/.config/claudio`, so it can't give itself more rules. A command is matched as text, so a broad rule you allow, such as `Bash(cat:*)`, could still reach the keys through a pattern like `~/.config/claudio/s*`: keep the rules you allow narrow.

### When it needs more

Your Claude Code permission settings don't apply to it. When the brain wants something its rules don't cover, the command waits and claudio itself asks, in the same reply. It says only what the command is, never the whole of it, and shows the answers under it:

> May I run `gh pr create`?
> - **1** Yes, this once
> - **2** Always
> - **3** No

Press 1, 2 or 3 to answer at once, no Enter needed. Or answer by voice or by typing, in your own words: what counts is the last part that says yes or no, so “you don't need to spell that out. So yes, go ahead” is a yes.

- **yes** (or yeah, sure, okay, go ahead, do it, you're allowed): it runs, this once, and the reply goes on
- **always**: it runs, and `Bash(gh pr create:*)` is added to `settings.json`, for the rest of this run and every later one, with no restart
- **no** (or don't, stop, not now), or no answer within a minute: it doesn't run, and the brain says so
- **a question back**, such as “what would that do?”: it doesn't run yet, and the brain answers you; say yes to that answer and the same command runs without being asked about again
- **anything unclear**: claudio asks once more, “Sorry, yes or no?”

Talking while it asks doesn't pause it, and a reply you cut off answers no. When it's a folder outside the one you started in, claudio asks about the folder instead, the whole repo when it's in one: “May I go into the claudio folder?”

The rule covers the command's first plain words, up to three, so “always” to `gh pr create` doesn't allow all of `gh`. When a rule would allow far more than the request, claudio offers yes and no but not always: a command run through `env`, `sh -c`, `python -c`, `xargs` or a variable such as `GH_PAGER=cat`, a cmux command that starts a program, writing a file (a bare `Write` rule would allow any file), or claudio's own folder. Add a narrow rule to `settings.json` yourself for those. Events from your sessions, which nobody is there to answer, are never asked about: the command is refused. A yes counts only once the question is on screen, so an "okay" to the reply before it allows nothing. claudio asks, not the brain, so nothing the brain reads can approve itself.

To drop every check instead, for this run only, start `claudio --dangerously-skip-permissions` or say “slash permissions skip” and then yes. The brain can then run anything without asking; it is still told to hand work to sessions and to get your yes before deleting, overwriting or pushing.

### Allow more

`~/.config/claudio/settings.json` takes [Claude Code permission settings](https://code.claude.com/docs/en/settings#permission-settings): `allow` and `deny` rules, and `additionalDirectories`, folders the brain may read and search in as well as the one you start claudio in:

```json title="~/.config/claudio/settings.json"
{
  "permissions": {
    "allow": ["Bash(gh:*)", "WebFetch"],
    "deny": ["Bash(gh repo delete:*)"],
    "additionalDirectories": ["~/GitHub/ActurialCapital/claudio"]
  }
}
```

An `allow` file from an earlier version, one rule or folder per line, is moved into `settings.json` once, and kept as `allow.bak`. If `settings.json` can't be read when “always” adds to it, the old one is kept as `settings.json.bak`.

Saving the file yourself, or `mcp.json`, restarts the brain with it, keeping the conversation; “always” doesn't need to. Anything you allow, the brain can run without asking, so allow only what you'd let it do unwatched. It presses keys in a session's pane only to select the option you chose in that session's question, never for a permission prompt. Work goes to your sessions.

Its model and effort come from the `model` and `effort` settings. With `model` set to `default`, it uses your Claude Code default.
