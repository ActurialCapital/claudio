claudio talks and your sessions work. Use this page to send a task to a session, open new sessions, check what one is doing, and choose which of their reports you hear.

A session is an ordinary Claude Code session running in a cmux workspace. claudio knows each one by its workspace title.

## Choose the orchestrator

The orchestrator is the session that gets your tasks unless you name another. You pick it during setup. To change it, say "the orchestrator is Core now", or run:

```bash
claudio set orchestrator Core
```

To use a different orchestrator in one project, put a `.claudio.json` in that project:

```json title=".claudio.json"
{ "orchestrator": "Core" }
```

## Hand work to a session

When you ask for work, the brain sends it to the orchestrator through cmux's agent inbox and tells you so:

```transcript
› rebase 44 on main and run the tests
◆ Sending that to Sequencer.
  → cmux agent message
```

The message starts with a marker, so the session knows the words are yours and not the brain's:

```text
[spoken by the user, transcribed by claudio] rebase 44 on main and run the tests
```

The brain passes on your words and any detail you gave. It never puts the marker on something you didn't say.

To send work elsewhere, name the session: "ask Core to update the changelog". The brain addresses the session's own pane, not its workspace, so a handoff never lands in claudio's pane when claudio runs in the orchestrator's workspace.

A session can answer back with `cmux agent message --reply-to`. The reply lands in claudio's own cmux inbox; claudio checks it every few seconds and reads it to you, with a `▸ <session>  replied` line, unless it's muted or `narrate` is `none`.

## Open a new session

Ask for one and the brain opens it with cmux:

- "open a session called Core" creates a cmux workspace running `claude` in the project directory
- "open a terminal beside Sequencer" splits that workspace and starts a shell
- "open a Claude session in a new tab of Core" adds a surface running `claude` to that workspace

A new session takes a few seconds to start, so the brain waits before handing it work.

## Check on a session

Ask "what's Sequencer doing?" and the brain reads the last 60 lines of that session's screen and sums them up in a sentence or two.

The [state line](/docs/guide/on-screen#read-the-state-line) also shows the orchestrator's state, checked every 5 seconds:

| State | What its screen shows |
|---|---|
| `working` | "esc to interrupt": the session is running |
| `waiting on you` | a permission prompt or a numbered choice |
| `idle` | neither |

If the orchestrator stays `waiting on you` for 2 minutes, claudio tells you once, unless you're muted or it's already speaking.

To stop a running session, press <kbd>Esc</kbd> in its pane. claudio can't stop it for you.

## Hear what sessions report back

When claudio isn't running, each hook exits at once, so they cost nothing the rest of the time.

### A session finished your task

When a session finishes a turn on work you handed it in the last 30 minutes, claudio narrates the result under a header naming the request:

```transcript
▸ Sequencer  done  ·  for "rebase 44 on main and run the tests"
◆ Rebased, tests pass, nothing to fix.
```

### A session needs permission

When a session stops at a permission prompt, claudio shows the prompt as the session's pane has it, word for word, and tells you which session wants what:

```transcript
▸ Sequencer  needs permission
◆ Sequencer wants to run git push origin feature-44.
◆ Allow it for Sequencer?
  → 1 Yes
  → 2 Always
  → 3 No
```

Say yes, always or no, or press 1, 2 or 3. claudio itself, not the brain, reads your answer and types it into that session's pane: yes picks the prompt's plain Yes, always picks the option that keeps allowing it (offered only when the prompt has one), and no presses Escape. It never picks an option that switches the session's mode. Before typing, it checks the same prompt is still on screen; if you answered it in the pane meanwhile, nothing is pressed. Ask a question back ("what does that do?") and the brain answers; a yes in the next two minutes still counts. Say anything else and the prompt waits for you in its pane.

### A session asks you to choose

When a session asks a multiple-choice question, claudio reads the question and its options aloud, numbered, and waits. Tell it your choice and it confirms what it understood, then answers in the session's pane with [`claudio choose`](/docs/reference/cli#claudio-choose-surface-n). The brain decides which option you meant; `claudio choose` checks a question is on screen (never a permission prompt) and that the option exists, then types its number. For a question that takes several, name them all and it ticks each and submits. For an answer in your own words, it types them into "Type something". With several questions it answers each in turn and submits the review. You can always pick it in the pane yourself instead.

```transcript
▸ Sequencer  asks you to choose
◆ Sequencer asks which branch to rebase onto.
  One, main. Two, release.
```

## Choose which reports you hear

The `narrate` setting decides what you hear from sessions:

| `narrate` | Finished tasks | Permission prompts and choices |
|---|---|---|
| `handed-off` (default) | from sessions you handed work to in the last 30 minutes | yes |
| `all` | from every session | yes |
| `none` | no | no |

Change it with `claudio set narrate all`. claudio also ignores:

- Its own brain's session
- Sessions outside cmux, since it can't tell which workspace they belong to
- Everything, while you're muted

<Callout type="warn">
A session reports back only if it started after the hooks were installed. If one stays silent, restart it, then run `claudio doctor`.
</Callout>
