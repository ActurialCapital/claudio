claudio talks and your sessions work. Use this page to send a task to a session, open new sessions, check what one is doing, and choose which of their reports you hear.

A session is a coding agent working on a task, such as a Claude Code session. Where your sessions live is the `backend` setting: `cmux` (each session is a cmux pane) or `bb` (each session is a bb thread). The rules on this page are the same on both; [on each platform](#on-each-platform) says where they differ.

## Choose the orchestrator

The orchestrator is the session that gets your tasks unless you name another. You pick it during setup, by its title. To change it, say "the orchestrator is Core now", or run:

```bash
claudio set orchestrator Core
```

To use a different orchestrator in one project, put a `.claudio.json` in that project:

```json title=".claudio.json"
{ "orchestrator": "Core" }
```

## Hand work to a session

When you ask for work, the brain sends it to the orchestrator. With permission checks on, claudio itself asks first, every time, and only your yes sends it; there's no “always” for sends:

```transcript
› rebase 44 on main and run the tests
◆ May I send "rebase 44 on main and run the tests" to Sequencer?
› yes
◆ Sending that to Sequencer.
```

A message of more than 25 words is read by its start: its first 12 words, then how many more there are. Say “read it all” and the brain reads you the whole message; a yes in the next two minutes sends it.

A question is never an order: “should I merge?” gets the brain's view, not a send. With [permission checks off](/docs/reference/cli#claudio---dangerously-skip-permissions), it sends without that question.

The message starts with a marker, so the session knows the words are yours and not the brain's:

```text
[spoken by the user, transcribed by claudio] rebase 44 on main and run the tests
```

The brain passes on your words and any detail you gave. It never puts the marker on something you didn't say.

To send work elsewhere, name the session: "ask Core to update the changelog". Sessions come and go, so whenever you name or ask about one, the brain lists them again rather than trust the list it started with.

## Open a new session

Ask for one ("open a session called Core") and the brain opens it, in the project you name or the one claudio runs in. claudio asks first, as for a send, when the new session starts with your task. A new session takes a few seconds to start, so the brain waits before handing it work.

## Check on a session

Ask "what's Sequencer doing?" and the brain reads what that session has been doing and sums it up in a sentence or two. It doesn't ask you first.

The [state line](/docs/guide/on-screen#read-the-state-line) also shows the orchestrator's state, checked every 5 seconds:

| State | Meaning |
|---|---|
| `working` | the session is running |
| `waiting on you` | it stopped at a permission prompt or a question |
| `idle` | neither |

If the orchestrator stays `waiting on you` for 2 minutes, claudio tells you once, unless you're muted or it's already speaking.

To stop a running session, stop it where it runs. claudio can't stop it for you.

## Hear what sessions report back

Three Claude Code hooks, which setup installs, report from every Claude Code session:

When claudio isn't running, each hook exits at once, so they cost nothing the rest of the time.

### A session finished your task

When a session finishes a turn on work you handed it in the last 30 minutes, claudio narrates the result under a header naming the request:

```transcript
▸ Sequencer  done  ·  for "rebase 44 on main and run the tests"
◆ Rebased, tests pass, nothing to fix.
```

Finished turns come from the hooks, so only Claude Code sessions report them.

### A session needs permission

When a session stops at a permission prompt, claudio shows the prompt, tells you which session wants what, and asks you:

```transcript
▸ Sequencer  needs permission
◆ Sequencer wants to run git push origin feature-44.
◆ Allow it for Sequencer?
  → 1 Yes
  → 2 Always
  → 3 No
```

Say yes, always or no, or press 1, 2 or 3. “Always” is offered only when the prompt has such an option. claudio itself, not the brain, takes your answer and gives it to the session, so nothing a session prints can answer it. Ask a question back ("what does that do?") and the brain answers; a yes in the next two minutes still counts. Say anything else and the prompt waits for you in the session.

Each prompt is read out once. When claudio is already asking you something, it reads the new one out and leaves you to answer it in the session.

### A session asks you to choose

When a session asks a multiple-choice question, claudio reads the question and its options aloud, numbered, and waits. Tell it your choice and it confirms what it understood, then answers the session with the option you picked. For a question that takes several, name them all. For an answer in your own words, say them. You can always answer in the session yourself instead.

```transcript
▸ Sequencer  asks you to choose
◆ Sequencer asks which branch to rebase onto.
  One, main. Two, release.
```

## Choose which reports you hear

The `narrate` setting decides what you hear from sessions:

| `narrate` | Finished tasks | Permission prompts and choices |
|---|---|---|
| `handed-off` (default) | from sessions you handed work to in the last 30 minutes | yes |
| `all` | from every session | yes |
| `none` | no | no |

Change it with `claudio set narrate all`. claudio also ignores:

- Its own brain's session
- Sessions outside the platform `backend` names, since it can't tell which session they are
- Everything, while you're muted

<Callout type="warn">
A session reports back only if it started after the hooks were installed. If one stays silent, restart it, then run `claudio doctor`.
</Callout>

## On each platform

The rules above hold everywhere. What changes is how claudio reaches a session:

| | [cmux](/docs/platforms/cmux) | [bb](/docs/platforms/bb) |
|---|---|---|
| A session is | a pane in a workspace, named by its tab or its Claude session title | a thread, named by its title |
| Hand over | `cmux agent message`, to the session's own pane | `bb thread tell`, to the thread |
| Open | a workspace running `claude` with claudio's session prompt, so it acts on the marker without asking you to confirm again; or a split or tab in a workspace | `bb thread spawn`, your task as its first message |
| Check on one | the last 60 lines of its screen | its last answer, or its log |
| Prompts and questions | from the hooks; answered by keys typed into its pane | from bb; answered in bb |
| Replies | a session can answer back to claudio's inbox | not used: a finished thread is narrated |
| Stop one | <kbd>Esc</kbd> in its pane | Stop on the thread in bb |

The platform pages have the detail: [cmux](/docs/platforms/cmux) and [bb](/docs/platforms/bb).
