Talk to claudio as you would to someone next to you: no grammar to learn, and no wake word unless you [share the room](/docs/configure/listening#rooms-with-other-people). This page covers how it knows you've finished, how to talk over it, the few spoken commands, and its memory.

## Ask a question or ask for work

The brain sorts each turn into one of two kinds:

- **Discussing**: you're thinking out loud, asking what something is, or weighing options. The brain answers itself, briefly, reading the project's files when it needs facts
- **Doing**: you want work done in the code, the repo or the plan. The brain says in one sentence what it would send and to which session, and asks; it sends only after your yes. When you already said to send it (“tell Sequencer to…”), or [permission checks are off](/docs/reference/cli#claudio---dangerously-skip-permissions), it sends straight away and says what it handed over. It never does the work itself

Three jobs it does itself, never a session:

- **A note**: "write a note: call Michael about the columns". It asks where to save it, Desktop or Documents, unless you said, and calls it `notes.md` unless you name it. Each note starts with the date and goes at the end of the file. "Open my notes" shows it. It can write only `.md` and `.txt` files there; another folder gets the [allow question](/docs/reference/files#when-it-needs-more)
- **A lookup**: "search what Aura-2 costs". It searches the web, says the answer in a sentence or two with the source, and puts the links on screen; it never reads an address aloud
- **The browser**: "search Aura pricing in the browser", "open issue 727 in the browser". It opens the page, or a Google search, in your browser and says only "Opening it.", no answer

Replies are written for the ear: two to five short sentences, no paths spelled out. When the shape fits, the screen carries more than the voice:

- **Three or more parallel things** come as bullets, each item read aloud
- **A comparison on two or more factors** comes as a table, shown and not read; claudio says what it compares, then its take. Ask for a table yourself and you get just the table: "Here it is." and nothing after
- **Code** comes as a highlighted block, shown and not read; up to 10 lines claudio explains it, longer it says what it is
- **Bold** marks the word that matters and `code` a name you may type; the voice says them plainly

Casual talk stays plain sentences. The [persona](/docs/configure/persona) sets these rules, and you can edit it.

## When your turn ends

Deepgram Flux listens continuously and decides when you've finished. Three settings control it:

- **`eager_eot`** (default `0.3`): at this confidence the brain starts on your words. Its reply is generated and its first sentences are synthesized, but nothing plays yet
- **`eot`** (default `0.7`): at this confidence your turn is final. If the final words match what the brain started on, the held audio plays at once. If they differ, the early reply is dropped and a new one starts
- **`eot_timeout_ms`** (default `1500`): after this much silence your turn ends, whatever the confidence

If a turn still ends mid-thought ("Can you tell me"), or is plainly meant for someone else in the room, the brain says nothing and waits; finish your sentence and it answers the whole thing.

If you start talking again before your turn is final, the early reply is dropped. The state line shows how long the last reply took to its first word, and a reply that takes more than 3 seconds prints a `! slow` warning.

[Listening and turns](/docs/configure/listening) explains how to tune these numbers.

## Talk over a reply

With `barge_in` on, the default, you can talk while claudio speaks:

1. When you start talking, the reply pauses and the state line reads `paused`
2. If you say a real turn, the reply is cut and your words become the next turn
3. If you only say a backchannel ("mm-hm", "yeah", "right"), the reply picks up again at the sentence it was saying
4. If no turn ends within 3 seconds of your last word, the reply picks up again too

A backchannel is anything under two words, or made only of filler words. The [spoken reference](/docs/reference/spoken#backchannels) lists them.

<Callout>
On speakers, talking over claudio needs the echo canceller, or claudio hears itself. It's built from a small Swift file the first time you run claudio, if the Xcode command line tools are installed. Without them, wear headphones.
</Callout>

With `barge_in` off, the mic sends silence to the ears while claudio answers, from the end of your turn until the reply ends. Press <kbd>Enter</kbd> to cut it instead.

## Say a command

Say "slash" and a command. Up to two filler words before "slash" are fine ("um, slash mute", "okay so, slash stop"). Any other word before it makes it ordinary speech, so "add a slash command" goes to the brain.

| Say | What happens |
|---|---|
| "slash clear" | forgets the conversation and restarts the brain on a fresh one |
| "slash stop" | cuts the current reply |
| "slash mute" | cuts the reply and ignores everything you say until "slash unmute"; sessions go quiet too |
| "slash unmute" | listens again |
| "slash status" | says the orchestrator, model, effort, voice and memory |
| "slash help" | says the list of commands |
| "slash quit" or "slash exit" | says bye and quits |
| "slash model sonnet" | `default`, `sonnet`, `opus` or `haiku`; restarts the brain |
| "slash effort high" | `low`, `medium` or `high`; restarts the brain |
| "slash style brief" | `plain`, `brief` or `caveman`, or just "slash caveman"; restarts the brain |
| "slash code colors off" | code blocks as plain text; "on" brings colours back, "slash colors" alone flips them |
| "slash voice thalia" | any Aura-2 voice by name; the confirmation is already in the new voice |
| "slash name Roger" | what it answers to and calls itself; restarts the brain |
| "slash address me on" | only turns that start with its name count; "off" turns it off |
| "slash barge in off" · "slash eot 0.8" | any other setting, said as it reads; alone, one that is on or off flips |

An unknown model or effort gets a spoken list of the valid ones. An unknown command gets the help.

You can also change settings in plain words: "use Sonnet", "make the orchestrator Core". The brain runs `claudio set` for you, and the change is saved for next time. [Settings](/docs/configure/settings) lists every one.

## Type instead of talking

Typing works alongside talking, for when you can't talk:

- **A line of text** is a turn, as if you'd said it
- **A line starting with `/`** is a command: `/mute`, `/effort low`, `/clear`
- **<kbd>Enter</kbd> on an empty line** cuts the current reply. With `push_to_talk` on and the mic closed, it opens the mic for one turn instead
- **<kbd>Ctrl</kbd>+<kbd>C</kbd>** quits

## What the brain remembers

The brain resumes your last conversation when you start claudio again, if it's less than 7 days old. The banner shows `memory on` when it resumed and `memory fresh` when it didn't. If the old conversation can't be resumed, claudio starts fresh and says so.

To start over:

- Say "slash clear" to start a fresh conversation now
- Run `claudio forget` to start fresh on the next run
- Run `claudio set memory false` to turn memory off

### What it learns

When you correct it in a way that should hold next time, such as a word it keeps mishearing, what a name means, or how you like something done, the brain keeps the correction as a one-line rule with [`claudio learn`](/docs/reference/cli#claudio-learn-rule), after claudio asks you, with the rule on screen. The rules go in `learned.md` and come back at every start, even after `claudio forget` or a week away, so claudio gets better the more you correct it. It learns only from your own words, not from a web page, a file or a session.

To drop a rule, say so ("forget the rule about seven"): the brain runs [`claudio unlearn`](/docs/reference/cli#claudio-unlearn-words) with a few words from it, and asks which one if several match. To see or edit them all, open `~/.config/claudio/learned.md`. A dropped rule takes effect at once: claudio restarts the brain after its current reply, memory kept. A rule you add there by hand applies from the next start.

For "what did we do today" or "what did I ask yesterday", the brain reads that day's [transcript file](/docs/guide/on-screen#find-past-conversations) instead of relying on its memory, which mixes up days.
