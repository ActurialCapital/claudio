---

To change how claudio talks for a while, set a style: “slash style brief”. To change what it is told for good, add to the persona in a plain Markdown file:

```text
~/.config/claudio/prompt.md
```

claudio's own rules come from the package, so every update reaches you. This file holds only your additions: they are added after claudio's rules and win where the two disagree. It starts empty but for a comment explaining that. When you save it, the brain restarts with it, keeps the conversation when `memory` is on, and says it is back. You see `· persona changed; brain restarting`.

```markdown title="~/.config/claudio/prompt.md"
Call me Jean. When I ask about the farm, the repo is Hawaii-Farming/aloha-app.
```

## What the default persona says

These are claudio's own rules, from the package. Know them before you add to them, since the rest of claudio relies on some of them:

- **Write for the ear**: two to five short, plain sentences, no paths or URLs, since every sentence is spoken
- **Let the screen carry more when the shape fits**: bullets for three or more parallel things (each read aloud), a Markdown table for a comparison on two or more factors and a fenced block for code (both shown, never read, with a spoken line on what they show), **bold** and `backticks` for key words and names
- **Lead with the answer**: end with a question only when the next step is your call
- **Say the next step before a tool call**, in two to five words, so you hear something while it runs: “Checking the roadmap.”
- **Discuss or hand over**: answer questions itself, hand work to a session, and never do the work itself
- **Read the transcripts** for “what did we do today”, rather than trust its memory of past days
- **Use cmux**: hand over through the agent inbox with the marker, list sessions, read a session's screen, open workspaces, splits and tabs
- **Narrate events**: finishes in plain words, permission prompts read out but never answered, multiple-choice questions read out numbered
- **Change settings** with `claudio set`, and say first that a model, effort or style change restarts it

It also carries rules that keep the voice human, adapted for speech from [humanizer](https://github.com/blader/humanizer)'s list of AI-writing tells: plain words (“is”, not “serves as”), no forced groups of three, no inflated significance, at most one hedge, no chatbot wrapper such as “Great question”, and stop on the last fact.

The handover marker matters most: sessions rely on `[spoken by the user, transcribed by claudio]` to know the words are yours. Keep it if you rewrite the cmux lines.

## Fill in the placeholders

Two placeholders in the file are replaced each time the brain starts:

| Placeholder | Becomes |
|---|---|
| `{TRANSCRIPTS}` | the transcripts directory, `~/.config/claudio/transcripts` |
| `{KEYS}` | the names of the settings, each with its choices where it has a fixed set, without the API keys |

claudio also adds text you do not need to write:

- **Before the persona**: the style's instructions, when `style` is not `plain`
- **After the persona**: the orchestrator, the current settings, and the open sessions with their surface ids and directories, as they were when the brain started

The brain also reads `CLAUDE.md` files, the project's and your own, like any Claude Code session.

## Replace the whole persona

To write the persona from scratch instead, put a complete one in `prompt.md`, starting with “You are the voice in front of”, as the package's does. claudio then uses yours instead of its own, and warns at start that its newer rules can't reach it. Keep the cmux handover lines and the marker if you rewrite it.

Older versions copied the whole persona into `prompt.md`. If you never edited that copy, claudio turns it into an empty additions file the next time it starts. If you did, it keeps using your copy, with the same warning: move your changes into an additions file to get claudio's updates again.

## Switch the style

The `style` setting changes how claudio talks without touching the persona. It follows [claudish-to-english](https://github.com/gvzdv/claudish-to-english)'s idea of presets you can flip mid-session:

| Style | Sounds like |
|---|---|
| `plain` | the persona as written: two to five sentences |
| `brief` | one sentence a reply, two when the answer has two parts; no lead-in before a tool, and no question back unless the next step is yours; a summary, list or comparison goes on screen, as a table when there are two or more factors, else short bullets |
| `caveman` | at most six words a sentence, no articles or connectors, fragments; facts, names and numbers stay exact |

```transcript
› slash style caveman
· /style caveman
⚙ style → caveman  ·  brain restarting
◆ Back. Caveman now.
› what's left on the roadmap?
◆ Next: Sales. File fields still open. Main clean. Want Sales started?
```

Switch by saying “slash style brief”, by typing `/style brief`, or with `claudio set style brief`. The brain restarts and keeps the conversation when `memory` is on.

Each of your turns is tagged with the style, such as `(brief style)`, so the brain keeps to it. When the brain starts a tool without a lead-in, claudio still says “Looking.” or “Checking.”, so a tool call is never silence.

To keep a style for one project only, put `{ "style": "brief" }` in that project's [`.claudio.json`](/docs/configure/settings#per-project).
